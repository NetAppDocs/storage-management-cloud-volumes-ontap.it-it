= Implementa Cloud Volumes ONTAP con Quick create in AWS
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Puoi implementare Cloud Volumes ONTAP in Amazon Web Services (AWS), Microsoft Azure e Google Cloud utilizzando `Quick create` per un'implementazione più rapida sia nelle configurazioni a nodo singolo sia in quelle ad alta disponibilità (HA). Questo processo semplificato riduce i passaggi di implementazione rispetto al metodo avanzato, impostando automaticamente i valori predefiniti in un'unica pagina e riducendo al minimo la navigazione.

.Dettagli del sistema
. *Account/credenziali del cloud provider/progetto Google Cloud*: i dettagli dell'account e dell'abbonamento vengono popolati automaticamente in base al tuo agente della Console. Se hai più account o abbonamenti, seleziona quello che vuoi usare. Se un agente della Console non è disponibile, ti verrà richiesto di  https://docs.netapp.com/us-en/console-setup-admin/concept-agent-install-options.html["creare un agente Console"^]. Per _Google Cloud_, devi selezionare un abbonamento del marketplace con il nome del progetto.
. *Nome*: Immettere un nome per il sistema Cloud Volumes ONTAP (chiamato anche nome del cluster). La Console utilizza il nome del sistema (cluster) per denominare il sistema Cloud Volumes ONTAP e l'istanza di macchina virtuale. Utilizza inoltre il nome come prefisso per il gruppo di sicurezza predefinito, se si seleziona tale opzione.
. *Credenziali ONTAP*: Queste sono le credenziali per l'account amministratore del cluster Cloud Volumes ONTAP. Puoi utilizzare queste credenziali per connetterti a Cloud Volumes ONTAP tramite ONTAP System Manager o la ONTAP CLI. Puoi mantenere il nome utente predefinito _admin_ o cambiarlo con un nome utente personalizzato.


Per _Google Cloud_, se prevedi di utilizzare link:concept-data-tiering.html["livelli di dati"] o  https://docs.netapp.com/us-en/data-services-backup-recovery/concept-backup-to-cloud.html["NetApp Backup and Recovery"^] con Cloud Volumes ONTAP, devi abilitare *Service Account* e selezionare un account di servizio con il ruolo predefinito Storage Admin. link:task-creating-gcp-service-account.html["Scopri come creare un account di servizio"^]. L'account di servizio associato all'agente di Console https://docs.netapp.com/us-en/console-setup-admin/reference-permissions-gcp.html["dovrebbe avere i permessi richiesti"^].

. *Tag/Etichette*: I tag sono i metadati per le risorse AWS o Azure. La Console aggiunge i tag all'istanza Cloud Volumes ONTAP e a ciascuna risorsa associata all'istanza. Puoi aggiungere fino a 15 tag dall'interfaccia utente quando crei un sistema Cloud Volumes ONTAP e poi aggiungerne altri dopo la creazione. Per ulteriori informazioni, consulta:

.Distribuzione e configurazione
. *Tipo/topologia di implementazione*: Seleziona il tipo di implementazione che desideri utilizzare: nodo singolo, alta disponibilità (HA) in una singola zona di disponibilità (AZ), o HA in più AZ.
. *Configurazione di rete*: Inserisci le informazioni di rete che hai registrato nel foglio di pianificazione per regioni, VNets e sottoreti.
+
.. *Regione*: Per impostazione predefinita, viene selezionata la regione dell'account cloud associato alle risorse.
.. *Zona di disponibilità*: Puoi selezionare la zona di disponibilità in base al tipo di implementazione che scegli e al fatto che la regione selezionata supporti la tua zona.
.. *Sottorete*: Selezionare una sottorete per la regione.
+
[role="tabbed-block"]
====
.Per AWS
--
*VPC*: Per AWS, inserisci una rete Amazon Virtual Private Cloud (VPC) per la regione con una sottorete in base all'implementazione pianificata.

.Disponibilità elevata di AWS
Se hai selezionato una configurazione HA, inserisci le seguenti informazioni:

.HA in AZ singola
... *Accesso mediatore*: specificare le informazioni di accesso del mediatore.  Il mediatore è un'istanza separata che monitora lo stato di salute della coppia HA e fornisce il quorum in caso di errore.  Fornire il nome della coppia di chiavi per consentire all'istanza del mediatore di connettersi al servizio AWS EC2 e selezionare il metodo di connessione.


.HA in più AZ
... *Zone di disponibilità e mediatore*: seleziona le zone di disponibilità (AZ) per ciascun nodo e il mediatore e le subnet corrispondenti in cui desideri distribuire la coppia Cloud Volumes ONTAP HA.
... *Indirizzi IP flottanti*: se hai scelto più AZ, specifica gli indirizzi IP flottanti per i servizi NFS e CIFS e per la gestione del cluster e delle SVM. Gli indirizzi IP devono essere al di fuori del blocco CIDR per tutte le VPC nella regione. Per ulteriori dettagli, consulta link:https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/reference-networking-aws.html#requirements-for-ha-pairs-in-multiple-azs["Requisiti di rete AWS per Cloud Volumes ONTAP HA in più AZ"^].
... *Accesso mediatore*: specificare le informazioni di accesso del mediatore.  Il mediatore è un'istanza separata che monitora lo stato di salute della coppia HA e fornisce il quorum in caso di errore.  Fornire il nome della coppia di chiavi per consentire all'istanza del mediatore di connettersi al servizio AWS EC2 e selezionare il metodo di connessione.
... *Tabelle di routing*: se hai scelto più AZ, seleziona le tabelle di routing che includono rotte verso gli indirizzi IP flottanti. Se hai più di una tabella di routing, assicurati di selezionare quelle corrette. In caso contrario, alcuni client potrebbero non avere accesso alla coppia HA di Cloud Volumes ONTAP. Per ulteriori informazioni sulle tabelle di routing, consulta http://docs.aws.amazon.com/AmazonVPC/latest/UserGuide/VPC_Route_Tables.html["Documentazione AWS: tabelle di routing"^].


.Ricarica e servizi
*Abbonamento al Marketplace*: In AWS, seleziona l'abbonamento al Marketplace di AWS che desideri utilizzare con questo sistema Cloud Volumes ONTAP.

--
.Per Azure
--
*VNET*: Seleziona la rete virtuale di Azure (VNet) richiesta. Per informazioni sui requisiti VNet, consulta link:reference-networking-azure.html#networking-for-azure-vnet-encryption["Networking per la crittografia di Azure VNet"].

--
.Per Google Cloud
--
*VPC e sottorete*: Per Google Cloud, inserisci una rete Google Virtual Private Cloud (VPC) per la regione e una sottorete in base alla distribuzione pianificata.

.HA in una singola AZ o in più AZ
Se hai selezionato una configurazione HA, inserisci le seguenti informazioni: *Zona per i nodi 1 e 2 e il mediatore*: aggiungi le zone per i due nodi e il mediatore. *Connettività* Seleziona quattro VPC diverse per la configurazione HA e una subnet in ciascuna VPC. Per ulteriori informazioni su VPC-1, VPC-2 e VPC-3, consulta link:reference-networking-gcp.html#requirements-specific-to-single-node-systems["Regole per VPC-1, VPC-2 e VPC-3"].


NOTE: Cloud Volumes ONTAP 9.19.1 e versioni successive supportano link:concept-ha-google-cloud.html["dischi condivisi per configurazioni HA a zona di disponibilità singola"], rendendo l'istanza del mediatore opzionale o ridondante. In questa configurazione, non ti serve una zona mediatrice, una VPC e una subnet per la replica dei dati.

.Ricarica e servizi
. *Licenza*: Seleziona il tipo di licenza che desideri utilizzare con questo sistema Cloud Volumes ONTAP. Puoi scegliere tra le licenze Professional, Essentials e Freemium. Per informazioni sulle diverse licenze, consulta link:concept-licensing.html["Scopri di più sulle licenze Cloud Volumes ONTAP"^].
. *Servizi dati e funzionalità*: mantieni attivi i servizi o disattiva quelli che non vuoi utilizzare con Cloud Volumes ONTAP. In _Google Cloud_, per selezionare Backup and Recovery o per utilizzare NetApp Cloud Tiering, devi specificare l'account di servizio.
+
** https://docs.netapp.com/us-en/data-services-data-classification/concept-classification.html["Scopri di più sulla classificazione NetApp"^]
** https://docs.netapp.com/us-en/data-services-backup-recovery/concept-backup-to-cloud.html["Scopri di più su NetApp Backup and Recovery"^]
** link:concept-worm.html["Scopri di più sullo storage WORM su Cloud Volumes ONTAP"]
+

TIP: Se vuoi utilizzare WORM e il tiering dei dati, devi disabilitare Backup and Recovery e implementare un sistema Cloud Volumes ONTAP con versione 9.8 o successiva.



. * Account del sito di supporto NetApp *: se disponi di più account, seleziona quello che desideri utilizzare.
. Verifica o modifica i dettagli che hai inserito, quindi seleziona *Crea*.


In Azure, la sezione *Panoramica* mostra le risorse che verranno allocate al termine del processo di distribuzione.

In _AWS_, subito dopo aver creato il sistema Cloud Volumes ONTAP, NetApp Console avvia un'istanza di test nella VPC specificata per verificarne la connettività. Se il test ha esito positivo, la Console termina immediatamente l'istanza e poi avvia la distribuzione del sistema. Se la Console non riesce a verificare la connettività, la creazione del sistema non riesce. L'istanza di test è un' `t2.nano` (per la tenancy VPC predefinita) o un' `m3.medium` (per la tenancy VPC dedicata).

.Dopo aver finito
La console distribuisce il sistema Cloud Volumes ONTAP .  È possibile monitorare i progressi nella pagina Audit.

Se riscontri problemi durante la distribuzione del sistema Cloud Volumes ONTAP, esamina il messaggio di errore. Puoi anche selezionare *Ricrea ambiente* sul sistema per continuare con la distribuzione utilizzando la modalità  `Advanced` procedura guidata.


CAUTION: Una volta completata la procedura di distribuzione, non modificare le configurazioni di Cloud Volumes ONTAP generate dal sistema nel portale cloud di AWS o Azure, in particolare i tag di sistema. Le modifiche a queste configurazioni potrebbero causare comportamenti imprevisti o la perdita di dati.
